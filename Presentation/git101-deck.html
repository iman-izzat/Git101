Why it yelled: messages are code

feat(roster): add Alice to trainee roster type scope what & why, imperative
typemeaningthe robot does…
fix:bug fixpatches version 1.0.0 → 1.0.1
feat:new capabilityminor bump 1.0.0 → 1.1.0
feat!: / BREAKING CHANGE:breaks how people use itmajor bump 1.0.0 → 2.0.0
docs: chore:text / housekeepingno version bump (on purpose)

The message isn't decoration. It's machine input — CI reads it, releases are generated from it.

WATCH

Why anyone cares

2024. A team updates one library from 1.4.2 → 2.0.0 because "it's just a number".

Production dashboard dead at 8am. Why: 2.0.0 removed a command their code relied on. The maintainer had warned everyone — in the version number. Nobody read it.

The whole system works because someone wrote feat!: and a robot turned it into 2.0.0. That's why commitlint is a gate, not a suggestion.

#1 RULE: COMMIT OFTEN
YOU TYPE

Already committed the mess?

terminal
$ git log --oneline
a1b2c3d feat: reformat notes badly 9f8e7d6 docs: add roster 2c4a6e8 feat: workshop scaffold
$ git revert a1b2c3d
# a NEW commit that is the exact opposite of the bad one. History stays honest.
Golden rules — the only two "never"s of today:
① never git push -f (it rewrites shared history — the thing you must never do to teammates)
② never delete the .git folder (that IS the time machine)
distinction: restore = uncommitted damage; revert = committed damage. One line: 'revert makes a new commit, it does not delete history — your mistakes become the documentation of the fix.'
